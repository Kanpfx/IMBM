可以。下面按 **当前 Ares 文档的 API Reference 章节**整理。

接口栏只保留核心参数：

* `[...]`：可选参数。
* `...`：还有调优参数，动作表中可继续展开。
* Behavior 的调用方式通常是 `self.register_behavior(Behavior(...))`。
* `self.mediator.get_xxx` 多数是属性，**不加括号**。
* 文档仍在持续完善，因此这里只代表“当前文档化接口”，不保证覆盖仓库全部接口。([Ares SC2][1])

# 0. 文档章节划分

| 章节                          | 内容                       | 是否属于动作接口       |
| --------------------------- | ------------------------ | -------------- |
| Start here                  | 框架介绍、安装、特性               | 否              |

# 1. AresBot

这是 Bot 基类，负责生命周期和执行 Behavior。

| 接口                                                                                                     | 作用                           |
| ------------------------------------------------------------------------------------------------------ | ---------------------------- |
| `AresBot(game_step_override=None)`                                                                     | 创建 Ares Bot，可覆盖配置中的 GameStep |
| `mediator`                                                                                             | 获取统一的 `ManagerMediator`      |
| `get_build_structures(structure_unit_types, unit_type, build_dict=None, ignored_build_from_tags=None)` | 找出哪些建筑可以生产指定单位               |
| `on_before_start()`                                                                                    | 游戏正式开始前执行                    |
| `on_start()`                                                                                           | 游戏开始时初始化                     |
| `on_step(iteration)`                                                                                   | 每个游戏步执行                      |
| `on_end(game_result)`                                                                                  | 游戏结束时执行                      |
| `on_unit_created(unit)`                                                                                | 己方单位创建时触发                    |
| `on_unit_destroyed(unit_tag)`                                                                          | 单位被摧毁时触发                     |
| `on_unit_took_damage(unit, amount_damage_taken)`                                                       | 单位受伤时触发                      |
| `on_building_construction_started(unit)`                                                               | 建筑开始建造时触发                    |
| `on_building_construction_complete(unit)`                                                              | 建筑完成时触发                      |
| `register_behavior(behavior)`                                                                          | 注册并执行一个 Ares Behavior        |
| `register_managers()`                                                                                  | 注册 Ares 后台 Managers，通常由框架处理  |
| `structure_pending(structure_type)`                                                                    | 查询正在建造的指定建筑数量                |
| `structure_present_or_pending(structure_type)`                                                         | 判断指定建筑是否已有或正在建造              |
| `unit_pending(unit_type)`                                                                              | 查询正在生产的指定单位数量                |

其中真正与你的动作表有关的主要是：

```python
self.register_behavior(Behavior(...))
```

其他接口主要负责 Bot 生命周期和状态查询。([Ares SC2][2])

# 2. Individual Combat Behaviors

控制**单个单位**。当前文档列出 25 个 Behavior/组合接口。

| Behavior 接口                                                                     | 作用                        |
| ------------------------------------------------------------------------------- | ------------------------- |
| `CombatManeuver()`                                                              | 创建单单位动作优先级链               |
| `CombatManeuver.add(behavior)`                                                  | 按顺序加入动作；前面的动作成功后，后面的本帧不执行 |
| `AMove(unit, target[, success_at_distance])`                                    | 对位置或单位执行 A-Move           |
| `AttackTarget(unit, target[, extra_range])`                                     | 攻击指定单位                    |
| `DropCargo(unit, target)`                                                       | 运输单位在目标位置卸载               |
| `GhostSnipe(unit, close_enemy)`                                                 | Ghost 自动选择适合的目标释放狙击       |
| `KeepUnitSafe(unit, grid)`                                                      | 根据影响力 Grid 将单位移到安全位置      |
| `MedivacHeal(unit, close_allied, grid[, keep_safe])`                            | 医疗运输机治疗友军，同时考虑自身安全        |
| `MoveToSafeTarget(unit, grid, target, ...)`                                     | 在目标附近找安全点并移动过去            |
| `PathUnitToTarget(unit, grid, target, ...)`                                     | 基于 Grid 安全寻路到目标           |
| `PickUpAndDropCargo(unit, grid, pickup_targets, target, ...)`                   | 完整执行接人、运输、卸载流程            |
| `PickUpCargo(unit, grid, pickup_targets[, cargo_switch_to_role])`               | 接载指定单位                    |
| `PlacePredictiveAoE(unit, path, enemy_center_unit, aoe_ability, ability_delay)` | 预测敌人未来位置后释放范围技能           |
| `QueenSpreadCreep(unit[, cancel_if_close_enemy, pre_move_queen_to_tumor])`      | Queen 自动铺菌毯               |
| `RavenAutoTurret(unit, all_close_enemy)`                                        | Raven 选择位置释放自动炮台          |
| `ReaperGrenade(unit, enemy_units, retreat_target, grid, ...)`                   | Reaper 选择目标释放手雷           |
| `SiegeTankDecision(unit, close_enemy, target, ...)`                             | 根据敌人和目标决定坦克架起或收起          |
| `ShootAndMoveToTarget(unit, enemy_units, target, grid, ...)`                    | 向目标推进时优先射击附近敌人            |
| `ShootTargetInRange(unit, targets[, extra_range])`                              | 武器就绪时攻击射程内目标              |
| `StutterUnitBack(unit, target[, kite_via_pathing, grid])`                       | 武器就绪时射击，冷却时后撤             |
| `StutterUnitForward(unit, target)`                                              | 武器就绪时射击，冷却时前压             |
| `TumorSpreadCreep(unit, target)`                                                | 菌毯肿瘤向目标方向继续扩张             |
| `UseAbility(ability, unit[, target])`                                           | 通用 `AbilityId` 技能调用       |
| `UseAOEAbility(unit, ability_id, targets, min_targets, ...)`                    | 计算最佳范围技能位置并避免误伤或重复施法      |
| `UseTransfuse(unit, targets[, extra_range])`                                    | Queen 自动选择目标输血            |
| `WorkerKiteBack(unit, target[, should_attack])`                                 | 工人利用矿物穿越进行拉扯撤退            |

典型组合：

```python
maneuver = CombatManeuver()
maneuver.add(KeepUnitSafe(unit, grid))
maneuver.add(ShootTargetInRange(unit, enemies))
maneuver.add(StutterUnitBack(unit, target, grid=grid))
maneuver.add(PathUnitToTarget(unit, grid, destination))

self.register_behavior(maneuver)
```

`CombatManeuver` 的本质是**优先级执行器**，不是同时执行全部动作。([Ares SC2][3])

# 3. Group Combat Behaviors

控制整组单位，通常一次向多个 unit tag 下达相同命令。

| Behavior 接口                                                               | 作用               |
| ------------------------------------------------------------------------- | ---------------- |
| `AMoveGroup(group, group_tags, target)`                                   | 整组 A-Move        |
| `KeepGroupSafe(group, close_enemy, grid[, attack_in_range_enemy])`        | 整组攻击射程内目标或撤向安全位置 |
| `PathGroupToTarget(start, group, group_tags, grid, target, ...)`          | 为整组计算一次安全路径并统一移动 |
| `StutterGroupBack(group, group_tags, group_position, target, grid)`       | 整组同步边打边退         |
| `StutterGroupForward(group, group_tags, group_position, target, enemies)` | 整组同步射击和前压        |
| `GroupUseAbility(ability, group, group_tags, target[, sync_command])`     | 整组释放同一个 Ability  |

这里通常需要同时传：

```python
group = list(units)
group_tags = {unit.tag for unit in group}
```

`sync_command=True` 表示等待组内所有单位都能使用该技能后再统一下令。([Ares SC2][4])

# 4. Macro Behaviors

控制经济、生产、建造和科技。

| Behavior 接口                                                       | 作用                    |
| ----------------------------------------------------------------- | --------------------- |
| `MacroPlan()`                                                     | 创建宏观动作优先级链            |
| `MacroPlan.add(behavior)`                                         | 加入宏观 Behavior         |
| `AddonSwap(structure_needing_addon, addon_required)`              | 人族建筑交换 Tech Lab/反应堆   |
| `AutoSupply(base_location[, closest_to, ...])`                    | 自动建造补给站、人口塔或 Overlord |
| `BuildStructure(base_location, structure_id, ...)`                | 选择工人和合法位置建造指定建筑       |
| `BuildWorkers(to_count)`                                          | 将工人生产到指定数量            |
| `ExpansionController(to_count[, max_pending])`                    | 将基地扩张到指定数量            |
| `GasBuildingController(to_count[, max_pending])`                  | 将气矿建筑补到指定数量           |
| `Mining(...)`                                                     | 自动分配矿工采矿、采气、转移和躲避危险   |
| `ProductionController(army_composition_dict, base_location, ...)` | 根据兵种构成补充生产建筑及挂件       |
| `RestorePower()`                                                  | 神族建筑断电后自动补水晶恢复供能      |
| `SpawnController(army_composition_dict[, freeflow_mode, ...])`    | 根据兵种比例和优先级生产军队        |
| `TechUp(desired_tech, base_location)`                             | 为目标兵种或升级补齐科技建筑链       |
| `UpgradeController(upgrade_list, base_location)`                  | 依次研究升级，并补充前置建筑        |

([Ares SC2][5])

## MacroPlan 的执行语义

```python
plan = MacroPlan()
plan.add(AutoSupply(base_location))
plan.add(SpawnController(army_comp))
plan.add(BuildWorkers(70))
plan.add(ExpansionController(4))

self.register_behavior(plan)
```

按照加入顺序检查，某个宏观 Behavior 成功执行后，本次计划停止。因此应把高优先级动作放前面，例如：

```text
防止卡人口
→ 生产军队
→ 生产工人
→ 扩张
```

([Ares SC2][5])

## 三个容易混淆的生产接口

| 接口                     | 负责什么         |
| ---------------------- | ------------ |
| `SpawnController`      | 从已有建筑生产单位    |
| `ProductionController` | 补兵营、工厂、星港及挂件 |
| `TechUp`               | 补目标单位所需的科技链  |

# 5. ManagerMediator

`ManagerMediator` 是 Ares 后台 Manager 的统一访问入口：

```python
grid = self.mediator.get_ground_grid
units = self.mediator.get_units_from_role(role=UnitRole.ATTACKING)
```

它大部分是**观测、查询和内部状态管理**，不应全部放入 LLM 的游戏动作空间。([Ares SC2][6])

## 5.2 ManagerMediator 方法：带括号调用

### 通用和 Manager 通信

| 接口                                                       | 作用                    |
| -------------------------------------------------------- | --------------------- |
| `add_managers(managers)`                                 | 注册后台 Managers，主要供框架使用 |
| `manager_request(receiver, request[, reason], **kwargs)` | 直接向某个 Manager 发请求     |

### Unit Role 和 Squad

| 接口                                          | 作用                 |
| ------------------------------------------- | ------------------ |
| `assign_role(tag, role)`                    | 给单个单位分配角色          |
| `batch_assign_role(tags, role)`             | 批量分配角色             |
| `clear_role(tag)`                           | 清除单位角色             |
| `switch_roles(from_role, to_role)`          | 将一个角色的所有单位切换到另一个角色 |
| `get_units_from_role(role[, unit_type])`    | 获取一个角色的单位          |
| `get_units_from_roles(roles[, unit_type])`  | 获取多个角色中的单位         |
| `get_all_from_roles_except(excluded_roles)` | 获取除指定角色外的单位        |
| `get_units_from_tags(tags)`                 | 根据 unit tag 获取单位   |
| `get_squads(role[, squad_radius])`          | 按角色生成或获取 Squads    |
| `get_position_of_main_squad(role)`          | 获取该角色主力 Squad 的中心  |
| `remove_tag_from_squads(tag)`               | 将单位从 Squad 中移除     |

### 单位空间查询

| 接口                                                                          | 作用             |
| --------------------------------------------------------------------------- | -------------- |
| `get_units_in_range(start_points, distances, query_tree[, return_as_dict])` | 查询一个或多个位置附近的单位 |
| `get_any_enemies_in_range(...)`                                             | 判断指定范围内是否存在敌人  |
| `get_own_unit_count(unit_type, ...)`                                        | 统计己方指定单位数量     |
| `get_is_detected(unit)`                                                     | 判断单位是否处于敌方侦测范围 |

### 战斗评估和安全性

| 接口                                                        | 作用                           |
| --------------------------------------------------------- | ---------------------------- |
| `can_win_fight(own_units, enemy_units, ...)`              | 模拟双方战力并返回 `EngagementResult` |
| `is_position_safe(grid, position[, weight_safety_limit])` | 判断位置在指定 Grid 上是否安全           |
| `find_closest_safe_spot(from_pos, grid[, radius])`        | 寻找最近安全位置                     |
| `find_lowest_cost_points(...)`                            | 查找 Grid 中代价最低的位置             |
| `find_low_priority_path(...)`                             | 计算低优先级或低成本路径                 |

`can_win_fight` 可以配置是否考虑单位距离、阵型以及是否忽略工人伤害。

### 寻路和地图分析

| 接口                                               | 作用                |
| ------------------------------------------------ | ----------------- |
| `find_path_next_point(start, target, grid, ...)` | 返回安全路径的下一个移动点     |
| `find_raw_path(start, target, grid, ...)`        | 返回完整路径点列表         |
| `get_flood_fill_area(start_point, grid, ...)`    | 对地图区域做 Flood Fill |
| `get_position_blocks_expansion(position)`        | 判断位置是否阻挡扩张点       |

### 建筑管理

| 接口                                                                            | 作用                  |
| ----------------------------------------------------------------------------- | ------------------- |
| `build_with_specific_worker(worker, structure_type, pos[, building_purpose])` | 用指定工人在指定位置建造        |
| `request_building_placement(base_location, structure_type, ...)`              | 请求合法建筑位置            |
| `can_place_structure(...)`                                                    | 判断指定建筑能否放置          |
| `building_position_blocked_by_burrowed_unit(...)`                             | 判断建筑位置是否被潜地单位阻挡     |
| `cancel_structure(structure)`                                                 | 取消建筑并同步清除 Ares 内部追踪 |
| `make_placement_available(...)`                                               | 释放已占用的建筑位置          |
| `move_structure(...)`                                                         | 移动或重新定位可移动建筑        |
| `request_warp_in(...)`                                                        | 请求神族折跃单位            |

直接调用普通取消命令可能导致 Ares 仍认为建筑处于计划中，所以文档推荐通过 `cancel_structure` 同步内部状态。

### 工人和资源管理

# 对你的动作表应该怎么分类

| 类别                            | 是否作为 LLM 动作        |
| ----------------------------- | ------------------ |
| Individual Combat Behaviors   | 是                  |
| Group Combat Behaviors        | 是                  |
| Macro Behaviors               | 是                  |
| `UseAbility` 中的具体 `AbilityId` | 需要另外建立子动作表         |
| ManagerMediator 查询属性          | 否，属于 observation   |
| ManagerMediator 角色/建筑修改接口     | 可作为后台辅助动作          |
| AresBot 生命周期                  | 否                  |
| Build Runner                  | 单独作为开局 DSL         |
| Tutorials                     | 不作为接口来源，只用于补充语义和示例 |

最终最合理的 JSON 分章是：

```text
ares_bot_lifecycle.json
combat_individual.json
combat_group.json
macro_behaviors.json
mediator_queries.json
mediator_commands.json
build_runner_dsl.json
ability_id_subset.json
```

其中真正给 IM 作为核心动作空间的，主要是：

```text
combat_individual
+ combat_group
+ macro_behaviors
+ 少量 mediator_commands
+ AbilityId 子集
```
