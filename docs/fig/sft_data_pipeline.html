SFT 数据筛选脚本流程说明

对应 scripts/gene_sft_data.py。这个脚本的核心思想是：从胜利局日志中找到“决策后未来一段时间内资产和人口增长较好”的旧 SunTzu 决策点，再把当时的 planner/action 对话历史导出成 SFT 样本。
一句话原理

它不是人工标注，也不是严格的因果归因；它用胜利局、动作有效性、planner 自检通过、未来指标增长、时间窗口均衡这几组启发式规则，自动筛出更像“优质专家轨迹”的对话样本。

总流程

1

读取 trace 日志

扫描固定路径下的 trace.json，并读取相邻的 config.json 判断种族。

2

过滤可用局面

只保留胜利局、指定种族、存在 obs/plans/actions，且动作全部有效、plan 自审通过的决策点。

3

计算未来收益

观察之后最多 15 个 trace 点，累计单位价值、建筑价值、军队人口、工人人口的折扣增量。

4

标准化与截断

对每个收益指标做标准化，合成 stand_score，再按阈值和时间窗口取 top 样本。

5

导出 SFT 格式

抽取 plan_chat_history 和 action_chat_history，转换成 from/value 格式输出。

输入数据与硬编码范围

日志路径

脚本只扫描两个固定 glob：

  • logs/sc2agent_0731/Flat48_Medium*/*/*/trace.json
  • logs/sc2agent_0731/Flat48_MediumHard*/*/*/trace.json

种族与结果

  • RACE = "Protoss" 是硬编码。
  • 只保留最后一条 trace 中 game_result == "Victory" 的对局。
  • 失败局、未完成局、其他地图/难度默认不会进入数据集。

单个决策点的保留条件

条件 脚本含义 筛选目的
obs 存在 当时的文本化观测可用。 保证可以还原 prompt 输入。
plans 非空且不超过 5 条 planner 给过可执行的短计划。 避免空计划或过长计划污染训练。
actions 非空 action agent 确实生成了动作。 避免只训练等待或无输出样本。
len(actions) == len(valid_actions) 所有生成动作都通过执行侧校验。 偏向收集合法动作样本。
"error_number": 0 planner critic 最后一轮认为计划没有违反规则。 偏向收集自审通过的 plan 样本。

未来收益打分

脚本用六个局面指标衡量当前决策点之后的增长，并把未来越远的增长折扣得越小。

收益指标

  • unit_mineral_value 增量
  • unit_vespene_value 增量
  • structure_mineral_value 增量
  • structure_vespene_value 增量
  • supply_army 增量
  • supply_workers 增量

时间折扣

对每个未来 trace 点，计算：

score[item] += (future[key] - current[key]) * 0.95 ** ((future_iteration - current_iteration) / 10)

最多向后看 15 个 trace 点，越近的变化权重越高。

标准化、加权与时间均衡

阶段 做法 影响
指标标准化 每个 score item 用 StandardScaler 变成均值 0、方差 1。 让不同量纲的矿物价值、气体价值、人口增长可以相加。
合成总分 stand_score = sum(z_scores) * 1.1 ** n_visible_enemy_units 看到敌军越多的局面被放大，偏向保留带战斗压力的样本。
分数阈值 只保留 stand_score > 1.5。 砍掉未来增长不明显或负增长的样本。
时间窗口 按 30s 分桶，每个桶取 top 60。 避免数据全部集中在中后期滚雪球阶段。

SFT 样本导出

脚本最后不是重新构造 prompt，而是直接复用日志里的 chat history。

Planner 样本

  • 总是加入 plan_chat_history[-2]。
  • 以 50% 概率加入 plan_chat_history[-1]。
  • 如果历史长度足够，再以 50% 概率加入 plan_chat_history[-3]。

Action 样本

  • 总是加入 action_chat_history[-1]。
  • 统计 action 分布并画 action_distribution.png。
  • 输出文件名为 sc2-ds-Protoss.json。

导出时把 OpenAI 消息格式中的 role/content 文本替换成 from/value，即常见的 ShareGPT 风格 SFT 数据格式。

当前不足

  • 脚本面向旧 SunTzu 的 plans/action_chat_history 日志，不直接适配当前 IMBM 的 im_chat_history/bm_chat_history。
  • 只保留胜利局，会强烈偏向优势局和滚雪球局面。
  • 未来资产增长不等于当前动作质量，信用分配比较粗。
  • 自动经济、自动还击和之前已排队生产会混进收益，容易高估当前决策。
  • 阈值、窗口、top_k 都是经验参数，没有和训练后胜率闭环校准。
  • 相邻样本未来窗口高度重叠，容易产生重复和强相关样本。

可以提升之处

  • 改成 IMBM 版本抽取：支持 im_chat_history、bm_chat_history、directive、request_background。
  • 把 plan/BM 指令样本和 IM 动作样本分开导出，分别训练战略模型与执行模型。
  • 加入失败局和低分局，标记为反例或偏好数据，用于 DPO/RLHF 风格训练。
  • 把收益指标扩展到战斗结果：击杀价值、损失价值、敌方建筑摧毁、基地扩张、资源闲置率。
  • 做 action-level attribution：只评估动作相关单位和相关资源变化，减少自动逻辑干扰。
  • 加入去重和多样性约束，避免同一时间段、同一 build order 样本过密。
  • 记录筛选元数据，例如 score、game_id、time_seconds、map、difficulty，方便训练后回溯。
  • 把硬编码路径、种族、阈值、窗口、top_k 改成命令行参数或配置文件。
